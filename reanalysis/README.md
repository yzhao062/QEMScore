# Reproduction Guide for Third-Party Reanalyses

This directory contains the reproduction package for the five published learned quantum error mitigation (QEM) systems reanalyzed in the manuscript:

1. **Q-LEAR** (Muqeet et al., 2024; Sections 4.3, 4.4, 4.6; Appendices E, F, L.5, N)
2. **QRAFT** (Patel et al., 2021; Sections 4.3, 4.5, 4.6; Appendices L.5, N)
3. **ML-QEM** (Liao et al., Nature Machine Intelligence 2024; Section 4.7, Appendix O)
4. **Synergy CNN** (Cantori et al., EPJ Quantum Technology 2024; Section 4.7, Appendix O)
5. **Q-Cluster** (Patil et al., 2025; Section 4.7, Appendix O)

All code and data in this directory adhere to strict reproducibility standards:
- **Frozen Recipes & Seeds**: Retraining parameters, loss definitions, random seeds (e.g. 20260906, 20260904, 12527150, 42), and resample counts (10,000, 2,000) are preserved exactly as frozen before the evaluation runs.
- **Portability**: All hard-coded author paths have been replaced with command-line arguments and sensible defaults. No private credentials or environment paths exist.
- **Integrity**: Every generated output is tracked in `SHA256SUMS` and verified by `check_paper_numbers.py`.

## 3. System-by-System Reproduction Guide

### 3.1 Q-LEAR (Muqeet et al. 2024)

- **Hosted by original authors**: Training data CSVs (`training_data/`), test evaluation CSVs (`testing_data/`), application QASM files (`testing_circuits/`), and trained models.
- **Generated by this study**:
  - `outputs/qlear/field-report.json`: Full ladder evaluation report (41 fits, 6 applications, 8 IBM backends, 10 seeds, hardware and simulator panels, pointwise bootstrap intervals).
  - `outputs/qlear/cost-ledger.json`: Circuit evaluation counts, inference efficiencies, and ratio calculations.
- **Per-Fit Predictions**: The 41 per-fit prediction files (`pred-*.json`) generated during ladder refitting are not bundled in the package. The packaged `outputs/qlear/field-report.json` and `outputs/qlear/cost-ledger.json` contain the verified outputs from the original evaluation run. Rescoring requires refitting the 41-arm ladder first using `scripts/qlear/fit_field_half.py`.
- **Execution Commands**:
  ```bash
  # Step 1: Refit the 41-arm ladder from the upstream release to generate per-fit predictions (~20-30 min GPU / ~2-3 hr CPU)
  python scripts/qlear/fit_field_half.py <unpacked-qlear-release> <fits-out-dir>

  # Step 2: Score the ladder from fitted predictions and run reproduction panel (<10s)
  python scripts/qlear/score_field_half.py <fits-out-dir> outputs/qlear/

  # Step 3: Derive circuit cost ledger (<2s)
  python scripts/qlear/cost_ledger.py <unpacked-qlear-release> outputs/qlear/field-report.json outputs/qlear/
  ```
- **Expected Runtimes**: Scoring & cost derivation: ~12 seconds. Ladder refit: ~25 minutes.

### 3.2 QRAFT (Patel et al. 2021)

- **Hosted by original authors**: Shipped inside Q-LEAR under `QRAFT/`: `data_processed/inputData.csv` (10,155 rows) and `data_trained/outputData.csv` (1,524 rows).
- **Generated by this study**:
  - `outputs/qraft/qraft-panel-report.json`: Panel R (released predictions) and Panel M (matched retraining over 10 seeds) MAE scores and ratios across 5 IBM machines.
- **Execution Commands**:
  ```bash
  # Accepts either the unpacked Q-LEAR root or the QRAFT subdirectory:
  python scripts/qraft/score_qraft_panel.py <unpacked-qlear-dir> outputs/qraft/
  ```
- **Expected Runtime**: ~15 seconds.

### 3.3 S1: ML-QEM (Liao et al. 2024)

- **Hosted by original authors**: Jupyter notebooks (`docs/tutorials/h36_ising_4q_hardware_plot.ipynb`), circuit pickles, and raw predictions (`hardware_over_depth.pk`).
- **Generated by this study**:
  - `outputs/s1_ml_qem/s1_hw4q.npz`: Extracted tabular features (165 execution-independent descriptors, 4 noisy expectation values) across 3,000 rows (500 train, 2,500 test).
  - `outputs/s1_ml_qem/S1_score.json`: Primary split ($S = 0.5985$) and leak-free circuit split ($S = 0.5534$) bootstrap evaluations.
  - `outputs/s1_ml_qem/S1_saturation.json`: Descriptor saturation search.
  - `outputs/s1_ml_qem/S1_appendix.json`: Baselines, unmitigated noisy expectation values, and re-referenced ratios.
  - `outputs/s1_ml_qem/S1_phase3_adversarial.json`: Adversarial checks and sensitivity stress tests.
- **Execution Commands**:
  ```bash
  python scripts/s1_ml_qem/phase2_score.py outputs/s1_ml_qem/ outputs/s1_ml_qem/
  python scripts/s1_ml_qem/verify3_adversarial.py outputs/s1_ml_qem/
  ```
- **Expected Runtime**: Scoring: ~14 seconds. Adversarial verification: ~3 seconds.

### 3.4 S2: Synergy CNN (Cantori et al. 2024)

- **Hosted by original authors**: Zenodo release archive `S2_release_1.4.zip` containing test circuits and model weights.
- **Generated by this study**:
  - `outputs/s2_synergy/s05_score.json` & `s06_final.json`: Six evaluation panels across Fig 8a, 8b, 8c with bootstrap intervals (upper bounds $\le +0.2755$).
  - `outputs/s2_synergy/s04_saturation.json`: Polynomial descriptor saturation sweep.
- **Execution Commands**:
  ```bash
  python scripts/s2_synergy/s05_score.py outputs/s2_synergy/ outputs/s2_synergy/
  python scripts/s2_synergy/s06_consolidate.py outputs/s2_synergy/ outputs/s2_synergy/
  ```
- **Expected Runtime**: <2 seconds.

### 3.5 S3: Q-Cluster (Patil et al. 2025)

- **Hosted by original authors**: `data/training_20250307_2151.pkl` (145 rows $\times$ 12 columns) and `data/master_dict_ibm_brussels_new_20250307_2151.pkl` at https://github.com/hrushikesh890/Q-Cluster.
- **Licensing & Redistribution Policy**: The upstream Q-Cluster repository does not declare an open-source license. In accordance with copyright law, no raw upstream data rows or derived target tables (`S3_target_table.npz`) are bundled into this repository. Instead, users fetch the upstream repository via `download_upstream.sh` and build `S3_target_table.npz` locally in under a second using `scripts/s3_qcluster/build_target_table.py`.
- **Target Table Builder**:
  ```bash
  python scripts/s3_qcluster/build_target_table.py --upstream-path upstream/s3_qcluster --out-dir outputs/s3_qcluster
  ```
  This reads the verified pickle (SHA-256: `163747ce5d43f1433dcd641d771b47fe5bd94e660640e9855cd66b1b773a1eb8`) using standard Python (numpy + pandas, no Qiskit needed) and outputs `S3_target_table.npz` (145 rows $\times$ 10 numeric features).
- **Generated by this study** (packaged in `outputs/s3_qcluster/`):
  - `outputs/s3_qcluster/oof_predictions.npy`: Out-of-fold cross-validated predictions (shape 4 $\times$ 3 $\times$ 145) produced by this study's models (LinearRegression, ExtraTrees, GradientBoosting, XGBoost), containing zero copied upstream rows.
  - `outputs/s3_qcluster/RESULT-arms.json`: Primary 4-panel evaluation ($S = 0.8607$ to $0.9441$, reading `PRESENT`).
  - `outputs/s3_qcluster/RESULT-cluster-bootstrap.json`: 10,000-draw circuit-level cluster bootstrap.
  - `outputs/s3_qcluster/RESULT-selection-optimism.json`: Nested cross-validation optimism audit.
  - `outputs/s3_qcluster/RESULT-saturation.json`: Descriptor saturation diagnostics.
  - `outputs/s3_qcluster/RESULT-diagnostics.json`: Grouped-by-circuit splits and ExtraTrees evaluations.
  - `outputs/s3_qcluster/PHASE1-RECORD.json`, `PHASE2-RECORD.json`, `PRE-REGISTRATION.json`, `arm_meta.json`, `master_derived.json`.
- **Execution Commands**:
  ```bash
  # Once built via build_target_table.py (or pointing directly to upstream/s3_qcluster):
  python scripts/s3_qcluster/score_01_arms.py outputs/s3_qcluster/ outputs/s3_qcluster/
  python scripts/s3_qcluster/score_08_cluster_bootstrap.py outputs/s3_qcluster/ outputs/s3_qcluster/
  python scripts/s3_qcluster/score_12_selection_optimism.py outputs/s3_qcluster/ outputs/s3_qcluster/
  ```
- **Expected Runtime**: Table build: <1 second. All scoring scripts combined: ~15 seconds.

## 8. Author Machine Origin Path Redaction

During the experimental campaign, metadata source records logged local absolute filesystem paths from author machines (e.g. Windows user profile directories and temporary virtual environment paths). To ensure privacy and eliminate personal identifiers before archival, all absolute author paths in the following source records have been sanitized to the neutral placeholder `<local-path-redacted>`:
- `outputs/s1_ml_qem/RUN-RECORD-S1.json`
- `outputs/s2_synergy/PHASE1-manifest.json`
- `outputs/s2_synergy/PREREG-phase2.json`
- `outputs/s3_qcluster/PHASE1-RECORD.json`

All numerical outputs, random seeds, hyperparameter settings, hashes, and JSON schema structures remain identical and byte-for-byte preserved.
